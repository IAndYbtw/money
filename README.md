# FinBot — Telegram-бот для учёта и анализа трат

Бот записывает расходы и доходы обычными сообщениями, сам раскладывает их по
категориям, считает бюджеты и цели, находит подписки и объясняет через DeepSeek,
куда уходят деньги.

## Что умеет

- Запись трат и доходов текстом: «300 продукты», «такси 450», «+50000 зарплата».
- Несколько операций одним сообщением: «продукты 800; кофе 200».
- Автокатегории + свои правила (`/cat`).
- `/insights` — ИИ-разбор трат за неделю и календарный месяц.
- `/ask` — свободный вопрос по своим финансам с историей диалога.
- Цели с прогрессом и откладываниями (`/goal`, `/goaladd`).
- Бюджеты по категориям на месяц с предупреждением при превышении.
- Импорт CSV/PDF-выписок с дедупликацией (повторная загрузка не удваивает траты).
- `/undo` — отменить последнюю операцию; `/export` — выгрузить всё в CSV.
- Еженедельная сводка в выбранное пользователем время и часовом поясе.
- `/deletedata` — полное удаление своих данных.

## Структура

```
bot/
├── main.py             # хендлеры aiogram, планировщик, точка входа
├── db.py               # SQLite: схема, миграции, транзакции, бюджеты, цели
├── categorizers.py     # парсинг текста → сумма + автокатегория + доход/расход
├── analytics.py        # сводки, доходы/баланс, подписки, бюджеты, цели
├── ai.py               # DeepSeek API: промпты, таймауты, ретраи
├── importer.py         # разбор банковских выписок CSV/PDF
├── config.py           # чтение .env и валидация настроек
├── utils.py            # время/часовые пояса, формат сумм, нарезка сообщений
├── requirements.txt
├── requirements-dev.txt
├── .env.example
└── tests/              # unittest-тесты парсеров, БД и аналитики
```

## Запуск

```bash
cd bot
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполнить BOT_TOKEN и API_KEY
python main.py
```

Python 3.11+ (используется `zoneinfo`). База по умолчанию создаётся в
`bot/finbot.sqlite3`; путь можно переопределить через `DB_PATH`.

## Команды

| Команда | Что делает |
|---|---|
| обычное сообщение | записать трату: «300 продукты», «такси 450» |
| `+` или «зарплата» | записать доход: «+50000 зарплата» |
| `/insights` | анализ трат за 7 дней и текущий месяц (ИИ, кэш 24 ч) |
| `/ask <вопрос>` | вопрос по финансам с учётом истории |
| `/undo` | удалить последнюю запись |
| `/import` | инструкция по загрузке выписки |
| документ `.csv/.pdf/.txt` | импорт выписки |
| `/export` | выгрузить все операции в CSV |
| `/reset` | очистить историю диалога с ИИ |
| `/goal <сумма> <название> [ГГГГ-ММ-ДД]` | создать цель |
| `/goals` | цели, прогресс и сколько нужно откладывать |
| `/goaladd <id> <сумма>` | отложить на цель |
| `/goaldel <id>` | удалить цель |
| `/budget <категория> <сумма>` | лимит на календарный месяц |
| `/budgets` | исполнение бюджетов |
| `/delbudget <категория>` | удалить лимит |
| `/cat <слово> <категория>` | своё правило категоризации |
| `/cats`, `/delcat <слово>` | список и удаление правил |
| `/remind on\|off\|ЧЧ:ММ` | еженедельная сводка (по понедельникам) |
| `/timezone <зона>` | например `Europe/Berlin` |
| `/currency <знак>` | ₽, $, € |
| `/deletedata confirm` | удалить все данные пользователя |
| `/app` | Mini App, если задан `WEB_APP_URL` |

## Как хранятся данные

- SQLite, режим WAL и `busy_timeout` — планировщик и хендлеры не мешают друг другу.
- **Всё время в БД — UTC.** Часовой пояс пользователя хранится в `users.timezone`,
  границы недели/месяца и напоминания считаются в локальном времени.
- Схема обновляется миграциями в `db.init_db()` — старые базы не нужно удалять.
- Импортированные операции получают отпечаток (`tg_id + сумма + тип + заметка + дата`),
  поэтому повторная загрузка той же выписки пропускается как дубликат. Ручные
  одинаковые траты при этом не склеиваются.

## ИИ-часть

В `analytics.build_ai_summary()` формируется **агрегированный JSON**: суммы по
категориям, доходы, баланс, норма сбережений, изменения месяц к месяцу, подписки,
бюджеты и цели. Никаких номеров карт и реквизитов получателей в API не уходит —
это и дешевле по токенам, и безопаснее.

Пример:

```json
{
  "week": {"total": 12400, "by_category": [{"category": "Такси", "total": 4100, "count": 6}]},
  "month": {"total": 48000, "by_category": []},
  "month_income": {"total": 120000, "by_category": [{"category": "Доход", "total": 120000, "count": 1}]},
  "month_balance": 72000,
  "savings_rate_pct": 60,
  "month_over_month": [{"category": "Такси", "current": 7800, "previous": 3200, "change_pct": 144}],
  "subscriptions": [{"name": "яндекс плюс", "amount": 399, "period_days": 30, "days_since_last": 40, "likely_active": false}],
  "budgets": [{"category": "Еда вне дома", "limit": 15000, "spent": 16200, "remaining": -1200, "used_pct": 108, "over": true}],
  "goals": [{"id": 1, "title": "отпуск", "target": 100000, "current": 25000, "progress_pct": 25, "monthly_needed": 12500}],
  "currency": "₽",
  "timezone": "Europe/Moscow"
}
```

`ai.SYSTEM_PROMPT` задаёт жёсткие рамки: отвечать только по переданным цифрам,
не выдумывать траты, связывать выводы с бюджетами и целями. Если ответы стали
общими — в первую очередь дорабатывай именно системный промпт.

Два сценария:

1. `generate_insights(summary)` — `/insights`, один вызов без истории.
2. `answer_question(summary, question, history)` — `/ask`, последние 10 сообщений
   хранятся в SQLite (`chat_history`), переживают перезапуск; `/reset` очищает.

Кэш `/insights` — 24 часа, ключ по хэшу сводки. Клиент DeepSeek создаётся лениво,
с таймаутом и ретраями; без `API_KEY` бот падает на старте с понятным сообщением.
Дневной лимит запросов на пользователя — `AI_DAILY_LIMIT` (по умолчанию 30).

## Импорт выписок

CSV поддерживает два варианта:

- без заголовка: `-300, кофе` (отрицательная сумма — расход);
- с заголовками: распознаются `сумма/amount`, `описание/note`, `дата/date`,
  `тип/kind`, а также отдельные колонки `расход/debit` и `приход/credit`.

Кодировка определяется автоматически (`utf-8-sig`, `utf-8`, `cp1251`).
PDF разбирается best-effort через `pdfplumber` (таблицы, затем текстовые строки);
форматы банков различаются, поэтому CSV надёжнее. Файлы до 10 МБ,
не больше 2000 строк за раз.

## Тесты

```bash
cd bot
python -m unittest discover -s tests -v
```

Покрыты: парсинг сумм (десятичная запятая, тысячи, даты), категоризация по
границам слов, определение доходов, CSV/PDF-парсер, дедупликация импорта,
undo, бюджеты, цели, лимит ИИ, кэш, удаление данных и аналитика
(доходы/баланс, сравнение месяцев, подписки).

## Настройки `.env`

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен Telegram-бота (обязателен) |
| `API_KEY` | — | ключ DeepSeek (обязателен) |
| `DEEPSEEK_MODEL` | `deepseek-chat` | модель (`deepseek-reasoner` — сильнее, но дороже) |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI-совместимый endpoint |
| `DEEPSEEK_TIMEOUT` | `30` | таймаут запроса, секунды |
| `DEEPSEEK_RETRIES` | `2` | число ретраев |
| `DB_PATH` | `finbot.sqlite3` | путь к SQLite |
| `DEFAULT_TIMEZONE` | `Europe/Moscow` | часовой пояс новых пользователей |
| `DEFAULT_REMINDER_TIME` | `09:00` | время сводки по умолчанию |
| `AI_DAILY_LIMIT` | `30` | запросов к ИИ на пользователя в сутки (`0` — без лимита) |
| `WEB_APP_URL` | — | HTTPS-адрес Mini App; без него кнопка скрыта |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Деплой

- Запускать из каталога `bot/` (или задать абсолютный `DB_PATH`).
- Логи идут в stderr — подхватываются systemd/journald или Docker.
- SQLite в WAL-режиме: делай периодический бэкап файла базы (например,
  `sqlite3 finbot.sqlite3 ".backup backup.sqlite3"`).
- Для нескольких инстансов бота SQLite не подойдёт — нужен PostgreSQL.

Docker:

```bash
cd bot
docker build -t finbot .
docker run -d --name finbot --env-file .env \
  -e DB_PATH=/app/data/finbot.sqlite3 \
  -v finbot-data:/app/data \
  finbot
```

`DB_PATH` внутри контейнера лучше держать на volume (`/app/data`), иначе база
пропадёт при пересоздании контейнера.

## Что осталось за рамками

- Фронтенд Mini App: `/app` показывает кнопку только при заданном `WEB_APP_URL`,
  самого приложения в репозитории нет.
- Курсы валют: `/currency` меняет только символ, суммы не конвертируются.
- Полноценные миграции под PostgreSQL и мультипроцессный запуск.
